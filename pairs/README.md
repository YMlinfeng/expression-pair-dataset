# 通过验证的 pair 数据（成品在这里）

这里只放**通过严格验证**的 pair。每个目录里 `A_*.mp4` 和 `B_*.mp4` 就是一对：
两个人表情相同，其他都不同。`metrics.json` 是这一对的全部指标，
`per_frame_metrics.png` 是逐帧曲线。

## 01 生成路线（主推）—— 表情由构造保证相同

| | |
| --- | --- |
| A | `A_person_s18.mp4` 红发女性，室内暖色背景 |
| B | `B_person_s32.mp4` 金发女性，室外石墙背景 |
| 表情来源 | `driver_d0.mp4` 亚洲男性，绿幕 |
| 帧数 | 78 |
| 逐帧通过率 | 12.8% |
| rank-1 时序可辨识率 | 34.6% |
| 身份余弦 | 0.081（远低于 0.25 阈值，确认是两个人）|

A 和 B 是同一个 driver 分别驱动两个不同 source 得到的。两条视频的表情
参数逐帧完全相同（同一个张量写进去的，不是"看起来像"），
而人物、背景、头部姿态、光照全都不同。这是数据集要的形态。

`montage.png` 可以直接肉眼验证：三行分别是 driver / A / B，
同一列是同一帧，表情轨迹一致（中性 → 笑 → 笑 → 收）。

## 02、03 真实路线 —— 用于评测，不用于训练

两个真人演员念同一句台词、演同一种情绪，用音频 DTW 对齐后逐帧比对。

| 目录 | 演员 | 内容 | 帧数 | 逐帧通过率 | rank-1 |
| --- | --- | --- | ---: | ---: | ---: |
| 02 | 1004 vs 1014 | 同句台词，愤怒 | 101 | 7.9% | 55.4% |
| 03 | 1002 vs 1005 | 同句台词，恐惧 | 94 | 11.7% | 27.7% |

这两对是从 177 个候选里筛出来的（通过率 1.1%）。真实数据无法保证表情
严格相同，只能筛，所以产量必然极低——这也正是主推生成路线的原因。

## 逐帧通过率为什么只有 10% 左右

阈值卡在"单帧可辨识"这个粒度上：要求 A 的第 t 帧在 B 里的最近邻就是
第 t 帧（±1 帧内），而不是差不多的第 t±5 帧。人脸静止不动的片段
天然无法满足这个条件（静止时相邻帧本来就一样），这些帧会被判为不可测
而拒掉。通过的帧是表情真正在变化、且变化被逐帧对上的帧。

换句话说 10% 不是"质量只有 10%"，是"只有 10% 的帧能被严格证明相同"。
如果只要求情绪类别一致，通过率会接近 100%，但那就是你明确不要的
"差不多"的数据。
